## 🛠️ 2. अंतिम सायकलमध्ये सोडवलेल्या त्रुटी (Resolved Issues & Bug Fixes)

या अंतिम फ्रीझ टप्प्यात खालील ५ प्रमुख बाबी यशस्वीरीत्या सोडवण्यात आल्या:

### १. Windows वरील प्रत्यक्ष फोल्डर रीनेम (Physical Folder Rename on Windows)
- **मूळ समस्या (Problem):** UI मध्ये फोल्डरचे नाव बदलत होते, परंतु Windows Explorer मध्ये प्रत्यक्षात ते फोल्डर रीनेम होत नव्हते.
- **मूळ कारण (Root Cause):** Tauri Rust बॅकएंडमध्ये केवळ फाईल्ससाठी कमांड होती, डिरेक्टरी रीनेमसाठी स्वतंत्र Rust हँडलर नव्हता.
- **केलेला बदल (Fix):** `src-tauri/src/lib.rs` मध्ये `rename_native_folder` फंक्शन जोडले आणि `rename_native_file` ला डायरेक्टरी सुरक्षित बनवले.
- **चाचणी निकाल (Result):** Windows डिस्कवर फोल्डरचे नाव तात्काळ आणि सुरक्षितपणे बदलले गेले.

### २. अचूक टायपिंग केसिंग (Exact Typing Casing - No Force Upper)
- **मूळ समस्या (Problem):** युझरने कीबोर्डवर लहान अक्षरे टाईप केली तरी ॲप बळजबरीने Uppercase करत होते.
- **मूळ कारण (Root Cause):** इनपुट इव्हेंटवर ग्लोबल `.toUpperCase()` फंक्शन जबरदस्तीने चालवले जात होते.
- **केलेला बदल (Fix):** युझरच्या प्रत्यक्ष टायपिंगचा आदर करणारे `exact typing` लॉजिक लागू केले; युझरने ज्या केसमध्ये टाईप केले असेल तेच अक्षरे राहतात.
- **चाचणी निकाल (Result):** युझरने Caps Lock ऑन ठेवला तर कॅपिटल, ऑफ ठेवला तर स्मॉल अक्षरे अचूक सेव्ह होतात.

### ३. 'Add folder name in file' अनचेक असताना अनावश्यक कॅल्क्युलेशन
- **मूळ समस्या (Problem):** चेकबॉक्स अनचेक असतानाही फाईलच्या नावावर नको ती प्रक्रिया होत होती.
- **मूळ कारण (Root Cause):** ऑन-चेंज इव्हेंटमध्ये कंडीशन तपासण्यापूर्वी री-कॅल्क्युलेशन ट्रिगर होत होते.
- **केलेला बदल (Fix):** चेकबॉक्स अनचेक असल्यास कॅल्क्युलेशन तत्काळ बायपास करून मूळ फाईलचे नाव जैसे थे ठेवले जाते.
- **चाचणी निकाल (Result):** शून्य अनावश्यक कॅल्क्युलेशन, जलद गती.

### ४. सर्क्युलर क्यू नॅव्हिगेशन (Wrap-around Circular Queue Navigation)
- **मूळ समस्या (Problem):** शेवटच्या फाईलवर आल्यावर पुढे जाण्याचा मार्ग थांबत होता; पुन्हा पहिल्या फाईलवर जाता येत नव्हते.
- **मूळ कारण (Root Cause):** क्यू इंडेक्स `length - 1` वर पोहचल्यावर थांबणारा हार्ड स्टॉप कोड होता.
- **केलेला बदल (Fix):** `(currentIndex + 1) % totalFiles` अशा प्रकारे चक्राकार लूप (1..N..1) लागू केला.
- **चाचणी निकाल (Result):** शेवटच्या फाईलवर Enter किंवा Tab दाबल्यास आपोआप पहिल्या फाईलवर जंप होते.

### ५. आधीच्या फाईल्सचे स्मार्ट केसिंग सिंक (Smart Active Casing Sync)
- **मूळ समस्या (Problem):** आधी प्रोसेस केलेल्या फाईलवर पुन्हा जाऊन केसिंग बदलल्यास ते लगेच अपडेट होत नव्हते.
- **मूळ कारण (Root Cause):** जुन्या प्रोसेस झालेल्या फाईल्सचा स्टेट फ्रीझ होत होता.
- **केलेला बदल (Fix):** युझर आधीच्या फाईलवर गेल्यावर Enter किंवा Tab दाबल्यास सक्रिय केसिंग तात्काळ सिंक होते.
- **चाचणी निकाल (Result):** आधी प्रोसेस केलेल्या फाईल्सचे केसिंग विनाअडथळा त्वरित बदलता येते.

## ⚠️ 3. तांत्रिक मर्यादा आणि मार्गदर्शक सूचना (Known Limitations & Guidelines)

1. **Windows File Lock:** जर एखादी PDF फाईल Adobe Acrobat किंवा इतर सॉफ्टवेअरमध्ये आधीच उघडलेली असेल, तर Windows OS ती फाईल रीनेम करण्यास नकार देते. अशा वेळी फाईल इतर सॉफ्टवेअरमधून बंद करून रीनेम करणे आवश्यक आहे (ॲप यासाठी स्पष्ट सूचना दाखवतो).
2. **Windows 260-Character Path Limit:** Windows वरील जुन्या पाथ मर्यादेसाठी DocMitra सुरक्षित फॉलबॅक वापरते; तरीही अत्यंत लांब फोल्डर पाथ असल्यास खबरदारी घेतली जाते.
